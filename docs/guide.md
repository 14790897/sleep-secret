# 使用指南

## 装到手机上

到 [Releases](https://github.com/14790897/sleep-secret/releases) 下载最新一版的 APK：

| 包 | 装给谁 |
|---|---|
| `app-arm64-v8a-release.apk` | **绝大多数手机**，不确定就装这个 |
| `app-armeabi-v7a-release.apk` | 较老的 32 位设备 |
| `app-x86_64-release.apk` | 模拟器 |

没有上架任何应用商店，所以系统会要求你允许「安装未知来源应用」。
分期打包是为了体积：一个通用包约 140 MB，按 CPU 架构分开后每个约 50 MB。

Windows 桌面版在同一个 Release 里，但它**只是测试用途**——桌面没有 Android 那种
前台服务保活，整夜录音要求插着电、且系统电源计划设成「从不休眠」。

## 第一次打开：三件事

!!! tip "这三件事没做，第二天大概率拿到一份空报告"

### 1. 允许录音

没有麦克风权限，应用什么也做不了。

### 2. 允许通知，别跳过

录音期间会有一条常驻通知，告诉你它还在工作。拒绝通知不影响录音本身，
但**系统在后台清理时更容易把应用一并杀掉**：

> 通知权限被拒绝，录音期间不会显示常驻通知。录音本身不受影响，
> 但系统在后台清理时更容易把它一并杀掉。

### 3. 把省电策略改成「无限制」

小米、华为这类系统对后台应用管得很严。除了省电策略，通常还要：

- 允许**自启动**
- 在最近任务列表里**锁定**这个应用（防一键清理）
- 把电池优化设为「不优化」

不做这些，手机可能在后半夜把你整晚的录音清掉——应用本身没有任何办法对抗这一点。

## 一晚是怎么走完的

1. **睡前**：到「睡眠」页点一下大按钮开始录音。
2. **夜里**：屏幕可以关掉。录音期间通知栏有一条常驻通知；想确认麦克风有没有在工作，
   白天可以在录音页看电平条。手机放枕边、屏幕朝上、别盖东西。
3. **早上**：再点一次按钮结束。分析结果自动生成，「报告」页就会出现这一晚。

## 录音页上的那几行数字

| 显示 | 意思 |
|---|---|
| 处理窗口 | 一共切出多少个分析窗口（每个窗口 3 秒） |
| 送进模型 | 其中有多少个真的送进了模型 |
| 跳过 | 被能量门控跳过的（安静段） |
| 输入电平 | 当前音量和峰值，用来判断麦克风有没有被挡住 |

!!! note "默认没有「识别门槛」这条线"

    应用默认**不做能量门控**：所有声音都会送进模型分析，安静段也一样。
    这是量出来的结论——门控唯一的作用是省算力，它并没有在挡误报，
    挡误报的是模型自己。所以「跳过」这一行默认恒为 0，电平条上也没有红线。

## 「保留鼾声与呼吸信号片段」

在「关于」页。默认**开启**：每晚写出几 MB 的音频文件（一个事件一个），存在应用私有目录里，
只有鼾声事件和高危信号（倒吸气）会留，梦话和咳嗽不留。报告里对应的事件可以点开试听。

关掉之后应用不写出任何音频文件，只保留事件的时间点和类别——历史记录里也就没法试听。

!!! warning "开着这个开关时，导出的文件里就带音频了"

    导出去的文件里这部分是**声音本身**。如果你把导出目录设在网盘的同步文件夹里，
    它会跟着上传到云端。介意的话把它关掉，之后再导出就只有分析结果。
    详见[数据与隐私](privacy.md)。

## 把记录带到另一台设备上

「关于」→「数据导出」。可以导出到一个网盘的同步目录（靠你的网盘客户端同步），
也可以直接配坚果云 / WebDAV，让应用自己上传。

导入按**开始时刻**去重，同一晚不会重复进来——所以换设备时先导出、把目录同步过去、
在新设备上导入即可。

## 升级

应用没有自动更新。看到 [Releases](https://github.com/14790897/sleep-secret/releases)
有新版本时，下载同架构的 APK 覆盖安装即可，**睡眠历史会保留**。

!!! danger "不要卸载重装"

    卸载会连应用私有目录里的数据库和音频片段一起清掉，**历史记录无法恢复**。
    换手机之前先导出。
